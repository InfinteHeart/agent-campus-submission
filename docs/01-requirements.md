# 需求、用户与成功标准

## 用户与目标

内容团队需要处理待发布素材，核对元数据与内部规则，结合既有排期形成可确认的排期草稿。核心价值是明确风险、缺失信息、冲突和待确认项，减少错误排期和重复保存。

## 输入与范围

用户输入 request_id、素材 ID、渠道、带时区的要求时间、hard/preferred 标记；元数据、证明材料、规则和已有排期来自本地合成资料。支持一份请求中 1–5 项素材。

本项目交付 Python CLI、DeepSeek Flash 真实模型接入、离线 Mock、四个业务工具及结束工具、SQLite 草稿、测试和实际 Trace。不实现发布、界面、线上部署、多 Agent、完整媒体识别或生产级 Runtime。

## 六个必须验收点

| 验收点 | 可验证成功标准 |
| --- | --- |
| 正常排期 | 通过规则，按原要求时段保存 ready 草稿，有数据库记录 |
| 信息缺失 | 模型有补查入口则先补查；仍缺失则列出缺失字段，不伪造审核通过 |
| 规则风险 | 输出规则 ID 与风险，阻断或待人工核实，不自动豁免 |
| 时段冲突 | 模型观察占用后查询替代时段，保存待确认提案，原始 hard 要求不变 |
| 重复提交 | 同 request_id + material_id 只有一份草稿，原样重试不新增版本 |
| 保存失败 | 写入错误明确失败，事务回滚，不虚报成功 |

附加验收：更换占用后重复请求会重新决策；确认绑定版本并复查；并发保存最多一个成功占位；达到上限明确 incomplete；批量逐项返回结果。

## 业务约束

1. 审核通过、草稿已保存、用户已确认和已发布是不同事实。
2. 本项目所有 published 字段为 false，因为没有发布接口。
3. 改时只作为建议；用户确认只能来自独立 CLI 入口，模型无确认权限。
4. 待确认提案不占正式时段；ready 草稿占用。最终确认再次检查，不能保证未经确认的建议一直空闲。
5. 同渠道固定一小时整点排他占用；不处理任意长度区间、跨日搜索及节假日策略。
6. 模型可自行决定补查、替代查询、请求信息、结束；固定代码只落实参数、权限、事实和持久化约束。

## 数据声明

M01/M06 正常；M02 补查后仍缺证明；M03 命中合成阻断表达；M04 可从补充资料取得证明；M05 需人工核实。所有素材、证明编号、排期和规则均合成，无真实客户或隐私数据。规则不构成法律结论。
