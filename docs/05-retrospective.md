# 复盘与交付边界

## 最难的问题

一是区分模型决策与确定性约束。LangGraph 的条件边负责预算、模型错误和结束路由；查补充资料、查替代时段、保存或停止等业务动作仍由 DeepSeek 在观察工具结果后选择。工具白名单、审核前置条件和真实保存回执防止模型越权或虚报成功。

二是让幂等与最新排期同时成立。相同请求不能新增草稿，却仍需在占用变化后重新审核和查询。SQLite 保留同一草稿 ID，必要时递增版本；确认绑定具体版本、资料签名和建议时段，并在事务中再次核查占用。

## 实际发现与改进

反例检查发现原规则可能把授权状态 unknown、证明编号非空的素材判为通过；现在授权状态必须明确为 cleared，新增自动测试和真实模型边界场景。双时段占用场景表明，18:00 与 19:00 都不可用时模型会改选 17:00，仍等待用户确认。LangGraph 迁移后重新运行了六个必验点的真实模型场景和十五组离线场景。

## 用时与个人贡献

提交者估计亲自投入约 2 小时；这是提交者提供的估算，未将 Codex 自动执行时间计入个人投入。当前代码修改由 Codex 辅助完成；提交者作出了框架选择，迁移前亲自重跑反事实场景，并在当前 LangGraph 版本中亲自运行 normal、conflict 两条真实模型路径，核对输出与 Trace；[个人复核报告](../examples/personal-review/report.json)为 2/2 通过。提交者随后亲自运行 33 项自动测试，全部通过。AI 使用范围及版本边界见[AI 使用说明](04-ai-usage.md)。

## 已完成与限制

已完成 Python CLI、LangGraph 单 Agent 工作流、DeepSeek Flash 工具调用、四个本地业务工具、合成资料、SQLite 草稿、独立确认入口、防重复、回滚、执行上限、自动测试及实际运行证据。

未实现真实发布、完整图片或视频识别、跨日及任意长度时段、多用户鉴权和线上部署。规则是合成文本与元数据检查，不构成真实法律或内容合规判断。待确认提案不占正式时段，用户确认时必须复查。

题号按试卷四题顺序记为第 1 题；GitHub 地址与最终 commit SHA 应以最终推送结果为准。
