# 复盘与交付边界

## 最难的问题

最难的是把“模型选择动作”与“程序守住权限和事实”分清楚。只有固定分支不满足 ReAct；全部信任模型又容易越权改时或虚报保存。实现中将下一动作交给 DeepSeek，将审核前置条件、确认身份、时段排他和保存回执交给代码与数据库。

第二个难点是幂等与实时变化并存。同一请求不能新增草稿，但也不能直接重放旧建议。因此保存同一 draft_id，状态变化递增版本；请求输入指纹防止悄悄改要求；每次重新审核、查询；确认绑定具体版本。

## 实际学习与修改

首轮真实运行表明，单靠系统提示表达等距离候选偏好并不稳定。将排序变为工具明确提供的数据，模型更容易正确选择，且排序不等于用户授权。

另一次真实运行中，模型将已确认草稿误认为待确认；确定性结束校验拒绝错误状态，模型读取错误后修正。这进一步说明结构化工具调用仍需业务校验。
